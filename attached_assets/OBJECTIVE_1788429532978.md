# ROOT CAUSE YOU MUST ACCOUNT FOR

The current `sign-upload` Edge Function uploads Cloudinary assets using Cloudinary's normal `upload` delivery type.

Therefore existing files are public Cloudinary delivery assets using URLs similar to:

`https://res.cloudinary.com/<cloud>/image/upload/...`

or:

`https://res.cloudinary.com/<cloud>/raw/upload/...`

However, the current `get-signed-url` Edge Function attempts to construct an `authenticated` Cloudinary URL.

That is an architecture mismatch.

Additionally, the current `get-signed-url` function incorrectly inserts:

`to_type=<timestamp>`

into the Cloudinary delivery path and attempts to use that as an expiration mechanism.

This is invalid and must be removed.

A Cloudinary signed delivery URL must have a signature matching the exact delivery path/transformation being requested. Do not invent URL parameters to represent expiration.
